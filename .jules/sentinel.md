## 2025-02-14 - IP Spoofing Vulnerability in Edge Function Rate Limiting
**Vulnerability:** The rate limiting logic in the `submit-lead` Supabase edge function extracted the client IP from `x-forwarded-for` and used the first IP in the chain (e.g., `req.headers.get('x-forwarded-for')?.split(',')[0]`). This allowed attackers to spoof their IP address by injecting a fake `X-Forwarded-For` header, bypassing rate limiting entirely.
**Learning:** Using the first IP in an `x-forwarded-for` chain is inherently unsafe because the first IP is the one supplied by the original client, which can be easily spoofed. Furthermore, `x-forwarded-for` was prioritized over infrastructure-provided headers like `cf-connecting-ip`.
**Prevention:** Always extract client IPs for rate limiting by prioritizing infrastructure-provided headers like `cf-connecting-ip` or `x-real-ip`. When falling back to `x-forwarded-for`, extract the last IP in the chain (using `.split(',').pop()`), which is the IP added by the last trusted proxy in the chain, preventing IP spoofing vulnerabilities.
