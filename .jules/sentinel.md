## 2025-02-14 - Fix Hardcoded Novu Subscriber ID
**Vulnerability:** Insecure Direct Object Reference (IDOR) / Information Leak via a hardcoded `subscriberId` ('6a862cd6d65a21c4a9697574') in the `NotificationInbox` component. This allowed any unauthenticated visitor to automatically fetch and view notifications intended for this specific user.
**Learning:** Hardcoding test credentials or user IDs during development and accidentally committing them to production is a common pattern that can lead to severe data exposure. In components that rely on user context (like an inbox), the default state for unauthenticated users must be `null` or empty, not a placeholder ID.
**Prevention:** Never hardcode user IDs, API keys, or test credentials in source code. Ensure components requiring authentication initialize their user-specific state to `null` and conditionally render only when a valid, authenticated context is present. Use environment variables for configuration identifiers (like application IDs) but never for user-specific data that varies per session.
