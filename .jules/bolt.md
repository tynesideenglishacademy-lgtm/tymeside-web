## 2024-05-18 - React scroll event thrashing and state dispatcher overhead
**Learning:** Even though React 18 batches state updates and bails out when the new state equals the old state (using Object.is), calling the state dispatcher inside a raw `window.addEventListener('scroll')` listener means React is still asked to evaluate the update 60+ times per second. `requestAnimationFrame` alone throttles the evaluations to screen refresh rates, but explicitly checking if the new state differs *before* calling the setter entirely avoids invoking React's dispatcher overhead. This significantly reduces main thread blocking during continuous scrolling.
**Action:** When binding scroll listeners that update React state (e.g. for sticky navbars or scroll-triggered elements), always use `requestAnimationFrame` AND check if the next state differs from a local `current` variable before invoking the state setter.
